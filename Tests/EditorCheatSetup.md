# 통합 에디터 치트

## 사용

1. 스크립트 컴파일이 끝나면 플레이를 다시 시작한다
2. GameSession이 현재 씬에서 이름이 Editorcheat인 오브젝트를 찾아 EditorCheatPanel을 붙인다
3. 해당 오브젝트가 없으면 현재 씬에 Editorcheat를 임시 생성한다
4. Editorcheat 오브젝트 중심에 표시되는 에디터 치트 버튼을 누른다
5. 닫기를 누르면 원래 화면 조작으로 돌아온다

스크린샷의 Canvas_Static/Editorcheat는 활성 상태로 유지한다 부모 Canvas_Static도 활성 상태여야 한다
플레이 중 자동 추가한 컴포넌트는 플레이 종료 시 사라지며 다음 플레이에서 다시 연결된다
별도 Inspector 의존성 연결은 필요하지 않다
Editorcheat의 RectTransform Pos X와 Pos Y를 변경하면 버튼도 해당 중심 위치를 따라간다
버튼 크기는 화면 기준 120 x 30이며 RectTransform의 Width와 Height로 변경하지 않는다
열린 창은 버튼 근처에 표시되며 버튼과 창 모두 화면 경계 안으로 보정된다
Canvas 또는 RectTransform이 없는 자동 생성 오브젝트는 왼쪽 위에 표시된다
Screen Space Camera와 World Space Canvas는 Canvas의 World Camera 연결이 필요하다
CardHandController의 기존 Test Panel Target과 이전 카드 치트 UI 코드는 제거되어 연결할 필요가 없다

## 기능

- 적 피해 및 즉사와 플레이어 피해 및 즉사: 전투 중에만 가능
- 피해: 방어도부터 차감하며 입력한 값과 실제 체력 피해가 다를 수 있음
- 즉사: 방어도를 지우고 현재 체력만큼 피해를 가해 기존 승리 및 패배 흐름 실행
- 플레이어 회복 및 전부 회복: 살아 있는 플레이어가 있으면 맵과 캠프에서도 가능
- 방어 추가와 에너지 사용 및 복원과 약화 및 취약과 적 행동 재추첨
- 현재 참가자 초기화: 현재 적 종류를 유지하고 참가자를 새로 생성하며 전투 덱은 별도
- 기존 손패 드로우와 순번 버리기 및 전체 버리기와 덱 초기화
- 카드 ID로 보유 덱 추가: 실제 게임 세션의 덱에 추가하며 다음 전투부터 사용
- 카드 ID로 손패 추가: 손패 빈자리와 카드 존재 여부 확인 후 현재 전투에만 추가
- 코인 지급: 실제 CoinModel에 지급하므로 상점 구매와 공통 HUD에 반영
- 유물 지급: 현재 비활성 상태이며 보유 시스템 구현 후 InjectRelicGrant에 지급 함수를 주입

치트창이 열려 있는 동안 배경 Canvas의 GraphicRaycaster를 잠시 꺼서 버튼 클릭이 게임 UI로 전달되지 않도록 한다
게임 시간은 멈추지 않으며 닫기 또는 비활성화 시 원래 활성 상태의 Raycaster를 복원한다
기존 카드 치트창은 제거되었으며 손패 조작 기능은 통합창에서 계속 사용한다
기존 넘패드 단축키는 유지하되 에디터 전용으로 제한하고 입력 필드 편집 중에는 실행하지 않는다

## 검증

- 전투 중 적 즉사 후 승리 보상 표시와 플레이어 즉사 후 GameOver 표시 확인
- 맵과 상점에서 치트 버튼 표시 및 코인 지급 후 HUD 갱신 확인
- 보유 덱 추가 후 덱 목록을 다시 열어 추가 카드 확인
- 잘못된 카드 ID와 음수 및 큰 정수 입력 시 상태 변경 없이 오류 안내 확인
- 손패가 가득 찼을 때 추가가 거절되는지 확인
- 치트창을 닫고 원래 상점 카드와 맵 버튼을 클릭할 수 있는지 확인

신규 치트 클래스와 자동 연결 및 전투 단축키는 UNITY_EDITOR 조건으로 빌드에서 제외된다
유물 효과 적용과 유물 보유 모델은 이 작업에 포함되지 않는다
